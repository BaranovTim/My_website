Dialess

Demo: Dialess moves a dentist visit, start to finish (44 s)

Description

Dialess makes phone calls for you. You type what you need, for example "move my dentist visit from Wednesday to Friday afternoon". An AI calls the business in Lithuanian, talks to them, and tells you the result.

I built it for people who moved to Lithuania and don't speak the language, and for anyone who hates phone calls. It started at the Unfair Weekend AI hackathon in Vilnius (12–15 November 2026), where it took 4th place out of 84 teams (about 250 participants). I then entered it in IceHacks.

Key Features:

1. Type it, it calls:

  • Write your request in your own words, or say it.
  • Claude turns it into a short "call card": the goal, the business and your limits.
  • Nothing is dialled until you tap Confirm.

2. A live call you can follow:

  • Live transcript in Lithuanian and in your language.
  • If the business asks something, Dialess asks you and waits for your answer.
  • You can take over the call with your own voice at any time.
  • Call up to 3 places at once.

3. Safety rules in code, not only in prompts:

  • The AI always says it is an AI first.
  • It only agrees to times inside your limits. Plain code checks this.
  • No payments, card numbers or emergency numbers.
  • Calls show your own verified number. No audio is stored.

4. Apps:

  • iPhone and Android app, plus a website.
  • A demo mode plays a full call without dialling anyone.

Tech Stack:

  • Backend: TypeScript on Node.js 22, with no runtime dependencies.
  • AI and voice: Claude API, ElevenLabs voice agent, Twilio calls and live transcription.
  • Data and sign-in: Supabase (PostgreSQL).
  • App: React Native with Expo. Deployed on Railway.

Try it here: dialess.live. The code is private for now.

Balsas

What should Vilnius fix first?

Balsas

Description

Balsas ("voice" in Lithuanian) answers one question for Vilnius: what should be fixed first? Residents take a photo of a problem. Claude fills in the report. Reports from the same spot join into one problem. A public formula ranks every problem, so anyone can see why something is #1.

Key Features:

1. Photo reports:

  • Claude looks at the photo and fills in the category and the description.
  • A photo goes public only when the AI is sure it shows nothing private: no people, number plates or documents.
  • Anything unsure waits, blurred, for a moderator.

2. Real data from day one:

  • Imports the public reports from the city's Tvarkau miestą service every hour.
  • A news agent reads Lithuanian news sites (LRT, 15min, Delfi and more). Claude picks out articles about real problems at real places.

3. A ranking you can check:

  • The priority formula is published.
  • Every problem has a "Why is this #1?" page.
  • Residents can press "This matters to me too".

4. City map and City Health:

  • A map with layers, districts and problem markers.
  • Sensor data adds what residents can't see.

5. Three languages:

  • Lithuanian, English and Russian. The AI translates new texts in the background.

Tech Stack:

  • Backend: Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic.
  • Database: PostgreSQL 17 with PostGIS for maps.
  • AI: Claude API for photos, news and translations.
  • Web app: Next.js 16 and Tailwind 4. Runs with Docker.

The code can be found here: GitHub Repository.

Vanth (Trading Bot)

Crypto calls from 5 agents, with an honest record

Vanth (Trading Bot)

Description

Vanth is a crypto prediction app. For 25 coins it says when to enter, where to place the order, where to take profit and where to put the stop. It never touches your exchange account: you place the trade yourself. It also keeps a public record of how every call really did.

Key Features:

1. Five agents:

  • Agents 1–4 only measure: chart patterns and smart money, indicators, news, and order flow.
  • Agent 5 is the model. It learns which of those signals actually matter.

2. Three kinds of calls:

  • 4-hour calls with a limit order, a target and a stop.
  • Daily swing calls with a stop that follows the price.
  • A weekly long/short rotation on the most-traded futures.
  • A "smart money" check: did top traders on Hyperliquid take the same side?

3. Tested honestly:

  • Walk-forward tests: the models learn only from the past and are scored on the next 6 months (Sep 2023 – Sep 2026, after fees).
  • In these tests, strong 4-hour calls won about 72% of the time.
  • Tests are not live results, so the app shows a live record of every call.
  • Ideas that didn't help are written down and left out.

4. App and alerts:

  • Flutter app for Android and iOS.
  • Alerts for new calls, filled orders, "take a third off", target and stop.
  • 599 Python tests and 188 app tests.

Tech Stack:

  • Models and data: Python, pandas, NumPy, scikit-learn, LightGBM.
  • Server: Python API in Docker on one small server.
  • App: Flutter (Dart).

Not financial advice. The code can be found here: GitHub Repository.

My Token Usage

Description

My Token Usage is a one-page dashboard. It shows how many tokens you use in Claude Code, and about how much that would cost at Anthropic's API prices.

Everyone who opens it sees their own numbers. The page reads your Claude Code log files inside your browser. Nothing is uploaded.

Key Features:

1. Your stats:

  • Lifetime tokens, peak day, longest task and streaks.
  • An activity calendar: daily, weekly or running total.

2. What it would cost:

  • Estimated API cost: all time, this month, last 30 days and per active day.
  • Split by project, by model, by day and by kind of token.

3. Every session:

  • Each Claude Code chat with its title, project, length, prompts, tokens and cost.
  • Search and sort.

4. Private by design:

  • Logs never leave your computer.
  • A small Python server updates the page every 5 minutes, only on your own machine.

Tech Stack:

  • One HTML file with plain JavaScript, no framework.
  • Python 3 standard library for the auto-update server.

Sepira

(QR scanner included)

Sepira

Description

Sepira is a website designed to manage a system of goods, allowing for their creation, modification, and organization. This platform facilitates the allocation of goods into specific sections within a warehouse using only their QR codes. Workers can add items to the warehouse, retrieve them, and monitor quantities. All operations are supported by a PostgreSQL database.

The QR code scanner is implemented in JavaScript, while the backend leverages the Django framework written in Python. Additionally, there are unique features for superusers—individuals responsible for managing the database. Superusers have access to advanced functionalities, such as adding news updates to ensure workers stay informed about the latest developments within the warehouse, as well as tracking worker activities, including the time, item, and quantity involved in each operation.

Key Features:

1. QR Code Scanning:

  • Scans goods to track and allocate them efficiently within the warehouse.
  • Links scanned data to the user and timestamp, ensuring traceability.
  • Workers input the quantity after scanning, which updates the database.

2. Warehouse Operations:

  • Add goods to the warehouse.
  • Retrieve goods.
  • Update item quantities.
  • Return goods.

3. PostgreSQL Database:

  • Centralized storage for all data related to goods, users, and operations.

4. Superuser Features:

  • Manage the database.
  • Add and edit warehouse-related news.
  • Track worker actions, including time, items handled, and quantities.

5. News Feature:

  • Keeps workers informed about the latest updates, changes, and announcements.

6. User Roles:

  • Workers: Focus on day-to-day operations like scanning, adding, and managing goods.
  • Superusers: Handle administrative tasks and maintain data integrity.

7. Optimized Design:

  • The interface is specifically tailored for efficient interaction, prioritizing functionality to streamline warehouse operations.

AI Model for Clothing Recognition

Image classification project

AI Model for Clothing Recognition

Description

Clothing Recognition is a PyTorch-based image classification project built on the FashionMNIST dataset. The repository contains a custom convolutional neural network implementation, training and evaluation loops, utilities for prediction on sample images, and visualization scripts for performance analysis (precision/recall curves, confusion matrix, F1 vs confidence).

Key Features:

1. Model Architecture:

  • Custom CNN implemented as a torch.nn.Module.
  • Two convolutional stacks with ReLU activations and average pooling.
  • Final fully connected classifier producing logits for 10 classes.
  • Custom MinPool2d implementation included for experimentation.

2. Dataset & DataLoader:

  • Uses torchvision.datasets.FashionMNIST (28×28 grayscale images).
  • Automatic download to data_2 folder if needed.
  • Training and test sets wrapped in torch.utils.data.DataLoader with configurable batch size.

3. Training & Evaluation:

  • Training loop with SGD optimizer and CrossEntropy loss.
  • Accuracy computed per batch and printed per epoch.
  • Evaluation utilities returning loss and accuracy summary.

4. Prediction & Visualization:

  • Function to run model predictions on arbitrary samples and return class probabilities.
  • Plots sample predictions with true vs predicted labels (green for correct, red for wrong).
  • Precision–Recall curves per class and macro-averaged curve.
  • F1-score vs confidence threshold visualizations and precision/recall vs threshold charts.
  • Confusion matrix plotting using sklearn.metrics.

5. Metrics:

  • Precision, Recall, F1-score (weighted and macro as required).
  • Detailed classification report (per-class precision/recall/f1).

6. Requirements & Setup:

  • Python 3.x
  • PyTorch and torchvision
  • NumPy, Matplotlib, scikit-learn
  • Install dependencies: pip install torch torchvision numpy matplotlib scikit-learn

7. Usage:

  • Train the model and evaluate: run the main training script (e.g., python train.py or your notebook).
  • Make single-sample predictions using the provided prediction helper function.
  • View plots generated by evaluation utilities to analyze model performance.

8. Troubleshooting:

  • GPU not used: Ensure CUDA is available and PyTorch is installed with CUDA support.
  • Slow training: Reduce dataset size, increase batch size, or use GPU.
  • Poor accuracy: Try increasing model capacity, use data augmentation, or tune learning rate.

9. Future Improvements:

  • Add data augmentation (random crop, flips, brightness/contrast) to improve generalization.
  • Use more advanced architectures or pretrained backbones (transfer learning).
  • Implement model checkpoints and training resume functionality.
  • Provide a simple web demo for live webcam classification and visualization.

The code is available here: GitHub Repository.

Chess Board Detector

Chess Board Detector

Chess Board Detector

Description

Chess Board and Piece Detection System is a computer vision project designed to detect and analyze a chessboard using live video from a camera. The system processes frames in real time, identifies the board layout, and provides clear visual feedback including bounding boxes, labels, and coordinate data.

The program is written entirely in Python and uses the OpenCV library for image capture and processing. It allows users to view a live camera feed, detect the chessboard, and display detailed information such as square positions and grid overlays for analysis or integration into other chess-related applications.

Key Features:

1. Real-Time Processing:

  • Continuously captures frames from the camera feed.
  • Processes and analyzes each frame to detect the chessboard in real time.
  • Updates visual results dynamically as the camera moves or lighting changes.

2. Visual Feedback:

  • Displays bounding boxes and labels for detected board areas.
  • Shows coordinate information for grid positions.
  • Provides a grid overlay to visualize square divisions clearly.

3. Usage:

  • Run the main file board_finder.py to start full chessboard detection.
  • Outputs chessboard bounding box coordinates and the number of detected squares.
  • Generates a visual grid representation of the detected board.

4. Camera Setup and Controls:

  • Uses the default camera (index 0).
  • Press ‘q’ to quit the application.
  • Processes frames every 10 seconds by default.

5. Requirements:

  • Install dependencies with pip install -r requirements.txt.
  • Ensure the camera is connected and functional.
  • Use good lighting and a clearly visible chessboard for optimal results.

6. Troubleshooting:

  • Camera not opening: Check that it’s properly connected and not used by another program.
  • Poor detection: Adjust lighting or ensure the chessboard is in the frame and fully visible.
  • No board detected: Adjust parameters in the script to improve detection accuracy.

7. Future Development:

  • Planned integration with Meta AI Glasses for hands-free board tracking.
  • Future improvements will include piece detection and automated move recording.
